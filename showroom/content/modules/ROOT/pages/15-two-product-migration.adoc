= Two-product migration: shared Gateway, path isolation

[.lead]
*Estimated time*: ~50 minutes · *Strategy*: Migration Toolkit and/or APIShift

== Learning objectives

* Migrate *two* different 3scale Products (OIDC + API Key) into *one* RHCL namespace
* Map existing 3scale Applications to RHCL credentials (Kubernetes Secret vs Keycloak JWT)
* Isolate products on a *shared Gateway* with one HTTPRoute rule per path and method, plus one AuthPolicy per product
* Keep the 3scale rate as a *per-identity* counter, and publish both products with APIShift

NOTE: This layout is *not* pre-installed. Modules xref:04-explore-cl-oidc.adoc[4] and xref:05-explore-cl-apikey.adoc[5] keep *one Gateway per app* (`neuralbank-stack`, `nfl-wallet-prod`) so you can compare 3scale and RHCL side by side. This page is the *target pattern* you produce with Migration Toolkit or APIShift: one Gateway, products and backends divided by path, isolated by RHCL auth policies.

Terminology on this page: *RHCL* means Red Hat Connectivity Link (policies and CRDs). The only product name that keeps “Kuadrant” is xref:11-kuadrant-console.adoc[Kuadrant Console] for day-2 operations. YAML still uses `apiVersion: kuadrant.io/...` because that is the API group. `OIDCPolicy` and `PlanPolicy` are `extensions.kuadrant.io/v1alpha1`.

== Source: two products already in 3scale

The Products, Backends, Application Plans, and consumer Applications live in the *3scale* APIManager, which this workshop installs in namespace `3scale-system`. The workloads they call do *not* live there:

* Neuralbank Service → namespace `neuralbank-stack`
* NFL Wallet Service → namespace `nfl-wallet-prod`
* `neuralbank-3scale` and `nfl-wallet-3scale` hold the 3scale RBAC for those Products, not the HTTP services

[cols="2,2,3,2",options="header"]
|===
| Product | Auth | Backends (systemName → path) | Plans

| *Neuralbank API (OIDC)*
`neuralbank-oidc`
| OIDC (Keycloak realm `neuralbank`)
| Accounts → `/api/v1/customers` +
Transactions → `/api/v1/transactions` +
Lending → `/api/v1/loans`
| Basic 60/min · Premium 300/min

| *NFL Wallet API (API Key)*
`nfl-wallet-apikey`
| API Key (`user_key` query)
| Payments → `/api/v1/wallets` +
Cards → `/api/v1/cards`
| Basic 120/min · Premium 600/min
|===

Private base URLs stay on the existing Services (do not move the workloads in this example):

* Neuralbank backends → `http://neuralbank-backend-svc.neuralbank-stack.svc.cluster.local:8080`
* NFL Wallet backends → `http://nfl-wallet-api.nfl-wallet-prod.svc.cluster.local:8080`

== Credentials that already exist (carry them over)

The Products already have Applications with credentials. The migration does *not* invent new consumers — it re-homes the same identity into RHCL CRDs.

[cols="2,2,3",options="header"]
|===
| 3scale identity | RHCL target | How to carry it

| NFL Wallet Application `user_key`
| Opaque Secret in `business-apis` with labels `app: nfl-wallet`, `kuadrant.io/apikey: "true"`, and annotation `secret.kuadrant.io/plan-id` (`basic` or `premium`)
| Put the existing `user_key` value in `stringData.api_key`. Do *not* commit that value to Gitea. Use Sealed Secrets or External Secrets, and keep a placeholder in the chart. Callers can keep `?user_key=` during the transition; new clients send `X-API-Key`.

| Neuralbank Application `client_id` / `client_secret`
| Keycloak client in realm `neuralbank` (same issuer the 3scale Product already uses)
| Keep the client in Keycloak. An AuthPolicy `jwt` rule checks the Bearer token against `issuerUrl` and then allows only `azp == neuralbank-frontend` (or the 3scale Application `client_id`). The token is the credential. There is no consumer Secret.
|===

TIP: After migration, a wallet Secret never matches Neuralbank routes (different AuthPolicy selector). A Neuralbank Bearer token never matches wallet routes (different AuthPolicy). That is the isolation model.

== Target: one namespace, one Gateway, paths for products and backends

Create namespace `business-apis`. Deploy a single Gateway `business-gw` (GatewayClass `istio`). The public hostname is an OpenShift Route with edge TLS in front of the Istio Service `business-gw-istio`. Cross-namespace `backendRefs` need a Gateway API `ReferenceGrant` in `neuralbank-stack` and in `nfl-wallet-prod`.

Public host example: `business-apis.{cluster_domain}`

Path layout. The public path keeps a product prefix. The backend still sees the path it has today, because each rule rewrites the prefix off.

[cols="3,2,3",options="header"]
|===
| Public path | Method | Backend path after rewrite

| `/neuralbank/api/v1/customers`
| GET, POST
| `/api/v1/customers`

| `/neuralbank/api/v1/transactions`
| GET
| `/api/v1/transactions`

| `/neuralbank/api/v1/loans`
| GET
| `/api/v1/loans`

| `/nfl-wallet/api/v1/wallets`
| GET
| `/api/v1/wallets`

| `/nfl-wallet/api/v1/cards`
| GET
| `/api/v1/cards`
|===

Any other path or method on this Gateway is not routed. A `PathPrefix` of `/neuralbank` alone would publish URLs that 3scale never mapped.

Text diagram:

----
Client
  │  HTTPS (OpenShift Route, edge)
  ▼
business-gw-istio :8080   Gateway business-gw (HTTP listener)
  │
  ├── AuthPolicy business-gw-deny     default deny on the Gateway
  │
  ├── HTTPRoute neuralbank-route      one rule per path + method
  │     ├── URLRewrite                strip /neuralbank
  │     ├── AuthPolicy jwt + azp      Keycloak realm neuralbank
  │     ├── PlanPolicy + RateLimit    counter per token subject
  │     └── → neuralbank-backend-svc.neuralbank-stack:8080
  │
  └── HTTPRoute nfl-wallet-route      one rule per path + method
        ├── URLRewrite                strip /nfl-wallet
        ├── AuthPolicy API key        Secrets labeled app=nfl-wallet
        ├── PlanPolicy + RateLimit    counter per api key
        └── → nfl-wallet-api.nfl-wallet-prod:8080
----

NOTE: A hostname per product on the *same* Gateway (`neuralbank.{cluster_domain}`, `nfl-wallet.{cluster_domain}`) keeps today's public URLs and does not need a rewrite. Path prefixes put both products on one host and force every client to change the URL. This module uses the path layout so isolation is visible in one hostname. Use hostnames when you cannot change clients.

== RHCL policies in scope

[cols="1,3",options="header"]
|===
| RHCL resource | Role in this example

| *Gateway* + *HTTPRoute* + *Route*
| HTTP listener on port 8080. Public TLS is the OpenShift Route (edge). One rule per mapped path and method, with `URLRewrite`.

| *ReferenceGrant*
| Lets the HTTPRoute in `business-apis` select Services in the backend namespaces.

| *AuthPolicy* (Gateway)
| Default deny. A new HTTPRoute on this Gateway stays closed until it has its own AuthPolicy.

| *AuthPolicy* (wallet route)
| API key. Selector on product-labeled Secrets. Header `X-API-Key` and, for the transition, query `user_key`.

| *AuthPolicy* (neuralbank route)
| JWT against the Keycloak issuer, then an allow only when `azp` is the Neuralbank client. This is the check the curl test uses.

| *PlanPolicy* + one *RateLimitPolicy*
| Tiers Basic and Premium. The counter is the caller, not the route. Two RateLimitPolicies on the same HTTPRoute do not add up: one is `Enforced`, the other is `Overridden`.

| *APIProduct*
| Publish each product into Developer Hub.

| *TLSPolicy* / *DNSPolicy*
| For a certificate on the Gateway listener, or for external DNS. Not used here, because the Route terminates TLS.
|===

`OIDCPolicy` is the wrong object for this test. It drives a browser login (authorization code, `redirectURI`, cookie). The verify step sends a Bearer token and expects `200`. Use AuthPolicy `jwt` for that. Keep `OIDCPolicy` only if you also move the Neuralbank *web* login onto this host, and mark it `v1alpha1`.

== Example manifests (target shape)

Replace `{cluster_domain}` with your ingress domain. Review generated YAML from Migration Toolkit or APIShift before you apply it. If the tool emits one Gateway per Product, merge the listeners onto `business-gw` and keep the rules below. The chart default `connectivityLink.targetNamespace` is `kuadrant-system` on purpose (that is where the operator watches). This example overrides it to `business-apis` for the shared Gateway. That override is the target of this module, not a change to the workshop default.

=== Namespace, Gateway, and OpenShift Route

The HTTPS listener without `tls.certificateRefs` is not a valid public endpoint. This cluster's working Gateways listen HTTP on 8080. The Route presents the certificate.

[source,yaml]
----
apiVersion: v1
kind: Namespace
metadata:
  name: business-apis
---
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: business-gw
  namespace: business-apis
  annotations:
    networking.istio.io/service-type: ClusterIP
    kuadrant.io/namespace: kuadrant-system
spec:
  gatewayClassName: istio
  listeners:
    - name: http
      port: 8080
      protocol: HTTP
      allowedRoutes:
        namespaces:
          from: Same
---
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  name: business-apis
  namespace: business-apis
spec:
  host: business-apis.{cluster_domain}
  to:
    kind: Service
    name: business-gw-istio
  port:
    targetPort: http
  tls:
    termination: edge
    insecureEdgeTerminationPolicy: Redirect
----

Istio names the Service `<gateway-name>-istio`. Confirm it with `oc get svc -n business-apis` before the Route can be Admitted.

=== ReferenceGrant (one in each backend namespace)

Without these, the HTTPRoute stays `RefNotPermitted` and the call is not forwarded.

[source,yaml]
----

kind: ReferenceGrant
metadata:
  name: allow-business-apis
  namespace: neuralbank-stack
spec:
  from:
    - group: gateway.networking.k8s.io
      kind: HTTPRoute
      namespace: business-apis
  to:
    - group: ""
      kind: Service
---

kind: ReferenceGrant
metadata:
  name: allow-business-apis
  namespace: nfl-wallet-prod
spec:
  from:
    - group: gateway.networking.k8s.io
      kind: HTTPRoute
      namespace: business-apis
  to:
    - group: ""
      kind: Service

=== Default deny on the Gateway

A route AuthPolicy replaces this only for that route. Anything else attached to `business-gw` returns 403.

[source,yaml]
----
apiVersion: kuadrant.io/v1
kind: AuthPolicy
metadata:
  name: business-gw-deny
  namespace: business-apis
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: Gateway
    name: business-gw
  defaults:
    rules:
      authorization:
        deny-all:
          opa:
            rego: |
              allow = false
      response:
        unauthorized:
          code: 403
          headers:
            content-type:
              value: application/json
          body:
            value: '{"error":"Forbidden"}'
----

=== Neuralbank HTTPRoute

`ReplacePrefixMatch` strips the product prefix. The matched prefix `/neuralbank/api/v1/customers` becomes `/api/v1/customers`, which is what the backend already serves. Repeat the same filter on every rule.

[source,yaml]
----
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: neuralbank-route
  namespace: business-apis
spec:
  parentRefs:
    - name: business-gw
      namespace: business-apis
  hostnames:
    - business-apis.{cluster_domain}
  rules:
    - matches:
        - path:
            type: PathPrefix
            value: /neuralbank/api/v1/customers
          method: GET
        - path:
            type: PathPrefix
            value: /neuralbank/api/v1/customers
          method: POST
      filters:
        - type: URLRewrite
          urlRewrite:
            path:
              type: ReplacePrefixMatch
              replacePrefixMatch: /api/v1/customers
      backendRefs:
        - name: neuralbank-backend-svc
          namespace: neuralbank-stack
          port: 8080
    - matches:
        - path:
            type: PathPrefix
            value: /neuralbank/api/v1/transactions
          method: GET
      filters:
        - type: URLRewrite
          urlRewrite:
            path:
              type: ReplacePrefixMatch
              replacePrefixMatch: /api/v1/transactions
      backendRefs:
        - name: neuralbank-backend-svc
          namespace: neuralbank-stack
          port: 8080
    - matches:
        - path:
            type: PathPrefix
            value: /neuralbank/api/v1/loans
          method: GET
      filters:
        - type: URLRewrite
          urlRewrite:
            path:
              type: ReplacePrefixMatch
              replacePrefixMatch: /api/v1/loans
      backendRefs:
        - name: neuralbank-backend-svc
          namespace: neuralbank-stack
          port: 8080
----

=== AuthPolicy — Neuralbank JWT (Bearer, not the browser login)

`overrides` replaces the Gateway deny for this route. Missing or bad tokens are *401*. A valid token whose `azp` is not the Neuralbank client is *403*.

[source,yaml]
----
apiVersion: kuadrant.io/v1
kind: AuthPolicy
metadata:
  name: neuralbank-jwt
  namespace: business-apis
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: neuralbank-route
  overrides:
    rules:
      authentication:
        oidc:
          jwt:
            issuerUrl: https://rhbk.{cluster_domain}/realms/neuralbank
          credentials:
            authorizationHeader:
              prefix: Bearer
      authorization:
        neuralbank-client:
          opa:
            rego: |
              allow { object.get(input.auth.identity, "azp", "") == "neuralbank-frontend" }
      response:
        unauthenticated:
          code: 401
        unauthorized:
          code: 403
----

If the 3scale Application uses another `client_id`, put that value in the Rego `allow` line. Confirm the claim with the token payload (`azp`). Authorino must expose it on `input.auth.identity`.

=== AuthPolicy — NFL Wallet API key

The Secret below is the *shape*. Replace the placeholder at apply time from the live 3scale Application, or from External Secrets. A second Secret with `plan-id: premium` is the Premium tier. Same labels, different annotation, different key value.

`queryString.name: user_key` accepts the 3scale parameter while clients move to the header. Drop it after the cutover.

[source,yaml]
----
apiVersion: v1
kind: Secret
metadata:
  name: nfl-wallet-migrated-basic
  namespace: business-apis
  labels:
    app: nfl-wallet
    kuadrant.io/apikey: "true"
    authorino.kuadrant.io/managed-by: authorino
  annotations:
    secret.kuadrant.io/plan-id: basic
type: Opaque
stringData:
  api_key: "replace-from-3scale-application-user-key"
---
apiVersion: v1
kind: Secret
metadata:
  name: nfl-wallet-migrated-premium
  namespace: business-apis
  labels:
    app: nfl-wallet
    kuadrant.io/apikey: "true"
    authorino.kuadrant.io/managed-by: authorino
  annotations:
    secret.kuadrant.io/plan-id: premium
type: Opaque
stringData:
  api_key: "replace-from-3scale-premium-application-user-key"
---
apiVersion: kuadrant.io/v1
kind: AuthPolicy
metadata:
  name: nfl-wallet-apikey
  namespace: business-apis
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: nfl-wallet-route
  overrides:
    rules:
      authentication:
        api-key-auth:
          apiKey:
            selector:
              matchLabels:
                app: nfl-wallet
                kuadrant.io/apikey: "true"
          credentials:
            customHeader:
              name: X-API-Key
            queryString:
              name: user_key
      response:
        unauthenticated:
          code: 401
        unauthorized:
          code: 403
----

=== Plans and rate limits (per caller)

In 3scale, 60/min belongs to *one Application*. A Kuadrant `RateLimitPolicy` without `counters` shares that budget across every caller on the route. Count the API key for wallet, and the token subject for Neuralbank.

`PlanPolicy` compiles one RateLimitPolicy. On this cluster a second RateLimitPolicy on the same HTTPRoute is marked `Overridden` and is not enforced. Do not add another RateLimitPolicy "beside" the plan and expect both to run. Read `status.conditions` type `Enforced` after apply.

Wallet tiers follow the 3scale plans (Basic 120/min, Premium 600/min). The predicate reads the Secret annotation. The counter is the key, so two Applications on Basic each get 120/min.

[source,yaml]
----
apiVersion: extensions.kuadrant.io/v1alpha1
kind: PlanPolicy
metadata:
  name: nfl-wallet-plans
  namespace: business-apis
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: nfl-wallet-route
  plans:
    - tier: basic
      predicate: |
        auth.identity.metadata.annotations["secret.kuadrant.io/plan-id"] == "basic"
      limits:
        daily: 10000
        custom:
          - limit: 120
            window: 1m
    - tier: premium
      predicate: |
        auth.identity.metadata.annotations["secret.kuadrant.io/plan-id"] == "premium"
      limits:
        daily: 100000
        custom:
          - limit: 600
            window: 1m
----

Neuralbank has no Secret annotation. Map the tier from a Keycloak claim or realm role, and count `auth.identity.sub` so two users do not share the 60/min. The example below treats realm role `premium` as Premium and every other valid token as Basic. Create that role in the `neuralbank` realm only if you want a second tier. Until the role exists, every token matches Basic.

[source,yaml]
----
apiVersion: kuadrant.io/v1
kind: RateLimitPolicy
metadata:
  name: neuralbank-plans
  namespace: business-apis
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: neuralbank-route
  limits:
    premium:
      rates:
        - limit: 300
          window: 1m
      counters:
        - expression: auth.identity.sub
      when:
        - predicate: auth.identity.realm_access.roles.exists(r, r == "premium")
    basic:
      rates:
        - limit: 60
          window: 1m
      counters:
        - expression: auth.identity.sub
      when:
        - predicate: '!auth.identity.realm_access.roles.exists(r, r == "premium")'
----

A limit denial is *429*, not 403. 403 on these routes means the credential was accepted and the authorization rule rejected it (wrong `azp`, or the Gateway deny). 401 means no credential or a bad one.

Publish two `APIProduct` resources (`neuralbank-api`, `nfl-wallet-api`) targeting the matching HTTPRoute when you want Developer Hub discovery.

== Cutover

Leave the 3scale Products and the side-by-side Gateways in modules 4 and 5 running. This Gateway is a second front door.

. Apply the manifests and pass the checks in <<_verify_isolation>>.
. Point a test client at `https://business-apis.{cluster_domain}/neuralbank/...` and `.../nfl-wallet/...`. Wallet clients may still send `user_key` until you remove `queryString`.
. Move traffic when those checks stay green: change the client base URL, or add a second host on this Gateway that matches the old hostname and shift DNS.
. Roll back by pointing clients at the original 3scale or side-by-side host. Do not delete the 3scale Product as part of this exercise.

== Walkthrough with Migration Toolkit and APIShift

Both tools discover the same 3scale Admin API and can emit Gateway API + RHCL policies. Use either or both. Budget time to edit the YAML: the tools do not emit the rewrite, the ReferenceGrant, the Route, or the per-identity counter for you.

| Same — create a migration plan per Product (or one plan covering both)

| Transform
| Review AuthPolicy, RateLimitPolicy, PlanPolicy, HTTPRoute, APIProduct
| Same core mapping · optional AI assist via `litemaas`

| Target
| Export or apply into namespace `business-apis`

| Fold Gateways
| If the tool emits one Gateway per Product, merge listeners onto `business-gw`, then replace the generated HTTPRoutes with the per-path rules and `URLRewrite` on this page
| Same review step

| Credentials
| Create wallet Secrets from existing `user_key` values, outside Git. Keep Neuralbank Keycloak clients.
| Same

| Register
| Manual catalog / skip
| Confirm registration with Developer Hub scaffolder (`scaffolderToken` from `secrets-rhdh` / `BACKEND_SECRET`) — both APIProducts appear in the catalog
|===

== Verify isolation

Set the host once. Expect *401* with no credential, *403* with a credential the route does not accept, *200* with the right credential, *404* on a path 3scale did not map, and *429* when the caller exceeds the plan. The 61st Neuralbank call in one minute is the Basic-plan check (the first 60 return 200).

The curls use `nfl-wallet-demo-key-2024` only after that value is in a Secret in `business-apis` with the labels above. The copy that already exists in `nfl-wallet-prod` does not match this Gateway.

[source,bash,role="execute",subs="+attributes"]
----
HOST="https://business-apis.{cluster_domain}"

# No credential
curl -sk -o /dev/null -w "nb-none %{http_code}\n" "$HOST/neuralbank/api/v1/customers"
curl -sk -o /dev/null -w "nfl-none %{http_code}\n" "$HOST/nfl-wallet/api/v1/wallets"

# Wallet key on the Neuralbank path: 401 or 403 (this route wants a Bearer token)
curl -sk -o /dev/null -w "key-on-nb %{http_code}\n" \
  -H "X-API-Key: nfl-wallet-demo-key-2024" \
  "$HOST/neuralbank/api/v1/customers"

# Neuralbank token on the wallet path: 401 (this route wants an API key)
TOKEN=$(curl -sk -X POST "https://rhbk.{cluster_domain}/realms/neuralbank/protocol/openid-connect/token" \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -d 'grant_type=password' -d 'client_id=neuralbank-frontend' \
  -d "username={neuralbank_user}" -d "password={neuralbank_password}" \
  | python -c 'import sys,json; print(json.load(sys.stdin)["access_token"])')
curl -sk -o /dev/null -w "token-on-nfl %{http_code}\n" \
  -H "Authorization: Bearer $TOKEN" \
  "$HOST/nfl-wallet/api/v1/wallets"

# Right credential, right path
curl -sk -o /dev/null -w "nb-ok %{http_code}\n" \
  -H "Authorization: Bearer $TOKEN" \
  "$HOST/neuralbank/api/v1/customers"
curl -sk -o /dev/null -w "nfl-ok %{http_code}\n" \
  -H "X-API-Key: nfl-wallet-demo-key-2024" \
  "$HOST/nfl-wallet/api/v1/wallets"

# Same wallet key still accepted as the 3scale query parameter
curl -sk -o /dev/null -w "nfl-query %{http_code}\n" \
  "$HOST/nfl-wallet/api/v1/wallets?user_key=nfl-wallet-demo-key-2024"

# Path that 3scale did not map
curl -sk -o /dev/null -w "nb-extra %{http_code}\n" \
  -H "Authorization: Bearer $TOKEN" \
  "$HOST/neuralbank/api/v1/admin"

# Basic plan: 60 succeed, the 61st is 429
ok=0; limited=0
for i in $(seq 1 61); do
  code=$(curl -sk -o /dev/null -w "%{http_code}" -H "Authorization: Bearer $TOKEN" "$HOST/neuralbank/api/v1/customers")
  if [ "$code" = "200" ]; then ok=$((ok+1)); elif [ "$code" = "429" ]; then limited=$((limited+1)); fi
done
echo "nb-200=$ok nb-429=$limited"
----
