= Verify and Test the Migration

[.lead]
*Estimated time*: ~20 minutes

== Learning objectives

* Confirm Gateway / policies are Ready in the migrated namespace
* Test OIDC and API Key paths with curl against both 3scale and CL endpoints
* Validate that behavior matches the source application

The workshop already runs both products side by side. This module checks those *preinstalled* Connectivity Link resources (not a per-user `{user_name}-*-cl` namespace, which is only created if you apply the migration template in module 7).

* Neuralbank (OIDC) — namespace `neuralbank-stack`, host `https://neuralbank.{cluster_domain}`
* NFL Wallet (API key) — namespace `nfl-wallet-prod`, host `https://nfl-wallet.{cluster_domain}`

== Step 1: Verify the Gateways are programmed

[source,bash,role="execute",subs="+attributes"]
----
oc whoami
oc get gateway -n neuralbank-stack
oc get gateway -n nfl-wallet-prod
----

Expected: `PROGRAMMED: True`

== Step 2: Verify policies are enforced

[source,bash,role="execute",subs="+attributes"]
----
oc get authpolicy,ratelimitpolicy,planpolicy,apiproduct -n neuralbank-stack
oc get authpolicy,ratelimitpolicy,planpolicy,apiproduct -n nfl-wallet-prod
----

The AuthPolicy should show `ACCEPTED: True` and `ENFORCED: True`.

== Step 3: Test the migrated API (OIDC)

=== 3.1 — Without token (expect redirect)

[source,bash,role="execute",subs="+attributes"]
----
curl -s -o /dev/null -w "HTTP Status: %\{http_code}\n" \
  https://neuralbank.{cluster_domain}/api/v1/customers
----

Expected: `HTTP Status: 302`

=== 3.2 — Get a Bearer Token

[source,bash,role="execute",subs="+attributes"]
----
TOKEN=$(curl -s -X POST \
  "https://rhbk.{cluster_domain}/realms/neuralbank/protocol/openid-connect/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=password" \
  -d "client_id=neuralbank-frontend" \
  -d "username={neuralbank_user}" \
  -d "password={neuralbank_password}" \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["access_token"])')

echo "Token (first 50 chars):" && echo "$TOKEN" | head -c 50 && echo "..."
----

=== 3.3 — List customers on the *migrated* endpoint

[source,bash,role="execute",subs="+attributes"]
----
curl -s -H "Authorization: Bearer $TOKEN" \
  "https://neuralbank.{cluster_domain}/api/v1/customers" \
  | python3 -m json.tool | head -20
----

=== 3.4 — Same call through 3scale APIcast (for comparison)

[source,bash,role="execute",subs="+attributes"]
----
curl -s -o /dev/null -w "3scale HTTP Status: %\{http_code}\n" \
  -H "Authorization: Bearer $TOKEN" \
  "https://neuralbank-oidc-3scale-apicast-production.{cluster_domain}/api/v1/customers"
----

Both front doors use the same backend Service, `neuralbank-backend-svc`. On this cluster both return *200*. A 403 from APIcast means the Bearer has no `aud` claim or the Application `client_id` is not `neuralbank-frontend`. The full executable path is xref:16-path-oidc.adoc[Neuralbank OIDC].

== Step 4: Compare the resources side by side

=== Authentication resources

[source,bash,role="execute",subs="+attributes"]
----
echo "=== 3scale Product ===" && \
oc get product -n 3scale-system | grep neuralbank && echo && \
echo "=== Connectivity Link AuthPolicy ===" && \
oc get authpolicy -n neuralbank-stack -o wide
----

=== Rate limiting

[source,bash,role="execute",subs="+attributes"]
----
echo "=== Connectivity Link RateLimitPolicy ===" && \
oc get ratelimitpolicy -n neuralbank-stack -o yaml | grep -A5 "limits:"
----

== Step 5: Test NFL Wallet (API Key)

The wallet Gateway is already on `nfl-wallet-prod`. Call `/api/v1/wallets`.

=== Without API Key (expect 401)

[source,bash,role="execute",subs="+attributes"]
----
curl -s -o /dev/null -w "HTTP Status: %\{http_code}\n" \
  https://nfl-wallet.{cluster_domain}/api/v1/wallets
----

=== With API Key

[source,bash,role="execute",subs="+attributes"]
----
curl -s -H "X-API-Key: nfl-wallet-demo-key-2024" \
  "https://nfl-wallet.{cluster_domain}/api/v1/wallets" \
  | python3 -m json.tool
----

== Step 6: Browse in Developer Hub and Kuadrant Console

. Open *Developer Hub* and search for your migrated component in the *Catalog*.
. Check the *API* tab — the OpenAPI spec should be available.
. Check the *Kuadrant* section — the APIProduct should show as Published.
. Verify the *ArgoCD* annotation links to the correct application.
. Optional: open xref:11-kuadrant-console.adoc[Kuadrant Console] in OpenShift Console to list the APIProduct, manage keys, and open Swagger against the *gateway* URL (CORS / Bearer mapping may require the demo EnvoyFilter pattern described in module 5).

== Step 7: Validate the complete flow

Run this comprehensive check:

[source,bash,role="execute",subs="+attributes"]
----
echo "=== Neuralbank ===" && \
oc get gateway,httproute,authpolicy,ratelimitpolicy,planpolicy,apiproduct -n neuralbank-stack && echo && \
echo "=== NFL Wallet ===" && \
oc get gateway,httproute,authpolicy,ratelimitpolicy,planpolicy,apiproduct -n nfl-wallet-prod
----

All resources should exist and show healthy status.

== Migration checklist

[cols="1,1,3",options="header"]
|===
| Check | Status | Description
| Gateway PROGRAMMED | ✓ | Istio gateway is accepting traffic
| AuthPolicy ENFORCED | ✓ | Authentication is active
| RateLimitPolicy ENFORCED | ✓ | Rate limiting is active
| API returns 200 with valid credentials | ✓ | Backend is reachable through the new gateway
| API returns 401/302 without credentials | ✓ | Authentication is blocking unauthorized access
| APIProduct Published | ✓ | API is visible in Developer Hub
| ArgoCD Synced + Healthy | ✓ | GitOps is working correctly
|===

== Summary

You have successfully:

* Verified all Connectivity Link resources are deployed and enforced
* Tested the migrated API with the same credentials as the 3scale version
* Compared both environments running side by side
* Confirmed the migration preserved authentication, rate limiting, and API documentation
