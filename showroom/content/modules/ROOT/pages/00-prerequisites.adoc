= Prerequisites and Environment Sizing

[.lead]
*Estimated time*: ~10 minutes

== Learning objectives

* Confirm the prior knowledge this workshop expects
* Understand which platform components the lab already provisions
* Order the demo with 3 workers on `m5a.8xlarge` and leave `userCount` at 30
* Know how URLs and credentials differ between GitHub Pages preview and a live showroom

== Prior knowledge

You should be comfortable with:

* *Kubernetes / OpenShift* basics — namespaces, Deployments, Services, Routes
* *YAML* and declarative configuration
* *GitOps* concepts (desired state in Git, continuous sync with Argo CD)
* *Gateway API* awareness (Gateway, HTTPRoute) — deep expertise not required
* *Authentication models* — difference between OIDC / JWT and API keys

TIP: If you need a refresher on the 3scale side, open https://docs.redhat.com/en/documentation/red_hat_3scale_api_management/[Red Hat 3scale documentation] in another tab. For Connectivity Link, use https://docs.redhat.com/en/documentation/red_hat_connectivity_link/[Connectivity Link docs].

== What the lab already provides

When you join a deployed workshop instance, the cluster already includes:

* *3scale* (source) and *Connectivity Link / Kuadrant* (target) side by side
* *Red Hat Developer Hub*, *Keycloak (RHBK)*, *Gitea*, *Argo CD*
* *Istio* (Service Mesh / Gateway API data plane)
* Observability (Grafana, Thanos, Tempo) and the migration strategy set (Developer Hub Golden Path, Kuadrant Console, Migration Toolkit, APIShift)

You do *not* install these operators during the lab — you explore and migrate against them.

== How to open the lab

. Register (or receive) workshop credentials from the registration portal.
. Open the *Showroom* URL for your cluster (pattern: `https://showroom-showroom.{cluster_domain}`).
. Use the *Terminal* tab for `oc` / `curl`, and open *Developer Hub* in a new browser tab if the embedded panel fails OIDC login.

NOTE: The public https://maximilianopizarro.github.io/from-3scale-to-connectivity-link/[GitHub Pages] site is a *documentation preview*. Placeholders such as `apps.cluster.example.com` and `{cluster_domain}` are *not* live hosts. On a deployed showroom, those values are rewritten automatically to your cluster domain.

== Environment sizing

This demo is ordered with *3 workers*. `userCount` in `examples/helm/values.yaml` stays at *30*.

IMPORTANT: Workshop infrastructure is installed from the Helm *App-of-Apps* chart under https://github.com/maximilianoPizarro/from-3scale-to-connectivity-link/tree/main/examples/helm[`examples/helm/`]. That chart renders Argo CD `Application` resources for operators, demo apps, showroom, and migration UIs. The child chart `components/applicationsets` (enabled as `connectivity-link-applicationsets` in `values.yaml`) deploys the Argo CD *ApplicationSet* that discovers user Git repos in Gitea and keeps per-user Applications in sync — it is part of the same install path, not a separate manual step.

[cols="2,2,3",options="header"]
|===
| Form field | Value | Notes

| OpenShift Worker count
| *3*
| The demo system form does not offer more workers.

| OpenShift Worker instance type
| *m5a.8xlarge* (32 vCPU / 128 Gi)
| Use this. `m5a.4xlarge` is tight. `m5a.2xlarge` is too small for this stack.
|===
