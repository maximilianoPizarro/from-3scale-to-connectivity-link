== Welcome

This workshop is for *platform engineers, application architects, and SREs* who already use OpenShift. You should know namespaces, Routes, and what an Argo CD sync does. Gateway API and Istio are introduced in the lab; you do not need prior Kuadrant experience.

Migrate API management from *Red Hat 3scale API Management* to *Red Hat Connectivity Link* (Kuadrant) with a clear set of strategies — not a single button.

*Why migrate (business view):* teams want APIs that ship with the same GitOps cadence as the rest of the platform — less dual admin planes, clearer ownership for platform vs product teams, and a path that does not lock gateway policy into a separate CMS. Connectivity Link puts auth, rate limits, and discovery next to the workloads on Gateway API.

The workshop ships *four complementary approaches*. Explore pre-deployed 3scale and Connectivity Link apps side by side, then pick the path that fits the situation in the decision table below.

=== Which strategy

[cols="3,2",options="header"]
|===
| Situation | Start here

| A handful of APIs, and the team already delivers through GitOps
| xref:07-run-migration.adoc[Golden Path]

| 3scale is in production and you want a guided import of Products, plans, and auth
| xref:12-migration-toolkit.adoc[Migration Toolkit]

| Same import, and you also want a first draft from a model plus the API registered in Developer Hub
| xref:13-apishift-gateforge.adoc[APIShift]

| Policies already exist; you need keys, traffic, and Swagger day to day
| xref:11-kuadrant-console.adoc[Kuadrant Console]

| Two products (OIDC and API key) should share one hostname, split by path
| xref:15-two-product-migration.adoc[Two-product migration] after Toolkit or APIShift
|===

*Toolkit and APIShift* share the migration core. Use the Toolkit when the mapping must stay inside the cluster and a person reviews every step in the wizard. Use APIShift when the Product is large or unfamiliar and a draft HTTPRoute / policy plus a catalog entity saves time.

The model can invent paths or policy fields. Read the diff before Argo CD syncs it. Product metadata and the prompt leave the cluster to the workshop LiteMaaS endpoint. Do not point APIShift at a 3scale token you cannot rotate. The Toolkit does not call the LLM.

TIP: In the lab, run at least the *Golden Path* (module 7). Use Toolkit or APIShift when you want a GUI against the live 3scale Admin API. Use Kuadrant Console after policies exist.

Worked example — migrate *two* Products (Neuralbank OIDC + NFL Wallet API Key) onto *one* shared Gateway with path isolation: xref:15-two-product-migration.adoc[11. Two-product migration].

== What does not migrate automatically

Connectivity Link in this lab covers routing, authentication, rate limits / plans, GitOps, and day-2 UIs. It does not replace:

* 3scale *billing* and commercial plan pricing
* The 3scale *Developer Portal CMS* (themes, Liquid, CMS pages) — discovery moves to APIProduct + Developer Hub
* Custom *APIcast* policies (Lua / NGINX) — those need an EnvoyFilter, WASM, or a redesign

Detail and the concept map: xref:01-migration-overview.adoc#not-migrated[module 1, What this workshop does not cover].

== Workshop flow

image::workshop-flow.svg["Golden Path flow (left to right): Developer Hub migration template → Gitea → Argo CD sync → OpenShift → Gateway API → Kuadrant policies. Five large labeled boxes; best viewed full width on projector or laptop."]

TIP: On a shared laptop or projector, zoom the browser or open the image full-width so the five boxes stay readable.

Text alternative — Golden Path (Developer Hub) steps:

. Start in *Developer Hub* (Software Templates / catalog) — the Golden Path.
. Scaffold or migrate — manifests land in *Gitea*.
. *Argo CD* syncs desired state to OpenShift.
. *Istio Gateway* + *Kuadrant* policies (AuthPolicy / RateLimitPolicy / PlanPolicy) enforce traffic.
. Operate and migrate with the other strategies: *Kuadrant Console*, *Migration Toolkit*, *APIShift*.
